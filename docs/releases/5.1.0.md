# Sans Password Manager 5.1.0

Six roadmap items in one release, bundled because they share their machinery.
No format change — 5.1.0 reads and writes exactly the vaults 5.0.3 does.

## What's new

### Trash, with restore and delayed permanent deletion (roadmap 24)

Deleting a password or a typed record no longer removes it. It moves to a
**Trash**, where it waits until you either **Restore** it or delete it for good.
Permanent deletion is always a second, deliberate step — the per-item *Delete
forever*, or *Empty trash*. Until then a trashed item is gone from every list,
count, search and the security score, so nothing surfaces it by accident.

The state is a single `trashed_at` timestamp inside the record's own attributes,
so every path that already moves a record carries it along. In the terminal:
`spm trash list`, `spm trash restore <type> <id>` (or `password <id>`),
`spm trash empty`, and `spm trash purge [days]`.

### Favourites (roadmap 22)

Pin the records you reach for with a star; favourites rise to the top of their
list. It is a `favorite` flag in the same attributes column, per vault. In the
terminal: `spm favorite <type> <id>` and `spm favorite --off <type> <id>`.

### A Certificate record type (roadmap 32)

Store an X.509 certificate — and optionally its private key — and SPM reads the
**subject, issuer, validity, subject-alternative names, key and signature
algorithms, and the SHA-256 fingerprint** straight out of the certificate. It is
derived in pure Python, matching `openssl x509` **without** a certificate
library, a keychain, or the private key — exactly how SSH and GPG keys already
describe themselves. Because a record type is a schema entry, the certificate
appears across the CLI and the Dashboard from one definition, and its expiry
feeds the expiration tracking below.

### Expiration tracking, and in-app notification (roadmap 30 & 31)

One pass finds every secret that carries an expiry date — API tokens, credit
cards, identity documents, licences, and now certificates — and reports what has
already expired or is due within the next 30 days. It shows up as an **Expiring**
page with a sidebar badge, and as `spm expiring` (`--days N`, `--json`). There is
no daemon and no network call: it reads dates the vault already holds, when you
open the page or run the command.

### Saved searches / smart collections (roadmap 28)

Save a search by name and run it again from the search page. A saved search
*re-runs* its query rather than freezing a list, so it keeps finding records you
add later. Stored in one `META_SAVED_SEARCHES` row. In the terminal:
`spm searches list|save <name> <query>|delete <name>`.

## Compatibility

- **No format change.** 5.1.0 stays on vault format 6. The new per-record flags
  (`favorite`, `trashed_at`) and the saved-search row are additive, and a 5.0.x
  build still opens a 5.1.0 vault.
- **Exports are unchanged.** A trashed record is excluded from an export
  entirely, and the favourite flag is a local convenience, so the twenty export
  formats carry exactly the columns they did before.

## Testing

The core suite gained tests for the attributes codec (favourite and trashed
round-trip and survive an unrelated edit), soft-delete/restore/purge, favourite
toggling, the expiry scan's buckets, the certificate parser (its fingerprint and
validity checked against `openssl x509`), and saved-search CRUD. The Dashboard
suite exercises the Trash and Expiring pages, the favourite toggle, the new
sidebar entries and their badges, and the certificate record end to end, and
confirms a Dashboard delete moves an item to the trash and that emptying it is
the only permanent removal. Accessibility checks cover every new control.

## Upgrading

Nothing to do. Reinstall or redeploy the Dashboard. Your vault is untouched.
