# Sans Password Manager 3.12.0

Every release now carries two installable packages, and the CLI can finally
answer which version it is.

## `spm --version`

It did not exist. The flag fell through to the interactive banner, so asking a
packaged CLI which version it was opened a menu and waited — which is how the
packaging work found it, when a Homebrew formula's own test called it.

`spm --version`, `spm -V` and `spm version` all print the version and exit,
answered before dependency installation and the language prompt, as `help`
already was.

## A Termux package

`spm_<version>_all.deb`, attached to each release with its checksum. Termux
uses apt, so the unit of distribution is a `.deb`:

```bash
dpkg -i spm_3.12.0_all.deb
```

It installs `spm` into the Termux prefix and declares `bash`, `gnupg` and
`python` as dependencies, so a package that installs is a package that runs —
gnupg in particular is not optional, since without it the vault cannot be
opened at all.

The packaged launcher points directly at Bash inside the Termux prefix because
Android does not provide `/usr/bin/env`; the generated portable script remains
unchanged beyond that package-specific interpreter line.

Built with `ar` and `tar` rather than `dpkg-deb`: the machine that cuts a
release is not a Debian machine, and adding dpkg to the release job to produce
a file whose format is three tar archives in an ar container is not a trade
worth making. Reproducible for the same reason the archive is — same commit,
same bytes.

The Termux CI job installs it and runs it, rather than inspecting it. A `.deb`
that unpacks and a `.deb` that the package manager accepts are different
claims, and only the second matters.

## A Homebrew formula

`spm.rb`, attached to each release:

```bash
brew install --formula \
  "https://github.com/sansyourways/Sans_Password_Manager/releases/download/v3.12.0/spm.rb"
```

Generated per release rather than checked into the repository. A formula pins
the sha256 of one specific archive, so a committed one is either stale or
carries a checksum for an archive that no longer matches — and a wrong checksum
fails for every user at once. The generator refuses a malformed version or
checksum rather than emitting a formula that would.

## What this is not

Neither package is published to a package index.

Homebrew core has notability requirements that a single-maintainer project does
not meet. Termux's repository has its own submission process. Both are
decisions to take deliberately, with a maintainer's name attached, rather than
side effects of a build script.

What ships here is installable today without either, and the roadmap says so
rather than implying a `brew install spm` that does not exist.

## Compatibility

No vault format change and no migration. The packages install the same
generated `spm.sh` implementation the archive contains; the Termux package
changes only its interpreter line for Android's filesystem layout.
