# Sans Password Manager 4.2.0

Some entries are ones you would rather not have named on your screen. This
release lets you mark them, and keeps their names out of the password list
until you ask for them.

## What this is

A switch on Add and Edit. A hidden entry keeps its row in the password list —
its service name and username are replaced with dots — and a **Hidden** section
beside the folder filters shows them in full.

```text
ID  NAME                              USERNAME
1   Acme Admin   rotate  Work  #work  avery@example.invalid
3   ••••••••     rotate  Personal  hidden   ••••••••
4   GitHub       rotate                     dev@example.invalid
```

The username goes too. It is usually an email address, which names the service
as surely as the service name does.

## What this is not

**It is shoulder-surfing protection, not access control.** The entry is still
in the vault, still opens normally, and is still exported. Anyone with the
master password sees everything. The hint under the switch says exactly that,
because a feature called "hide" invites people to assume more.

Two consequences the implementation actually had to honour:

- **The redaction is done by the server.** A CSS blur would satisfy every
  visual check and leave the name sitting in the page source — a promise the
  page does not keep. What the regression suite asserts is the bytes on the
  wire, not the rendering.
- **A hidden entry is not findable by the name it is not showing.** The instant
  filter indexes the redacted text, so typing the name and watching a single
  row survive cannot undo, on the same page, the redaction that page just
  performed.

Hidden entries stay *listed* rather than vanishing. A vanished entry looks like
a lost entry, and the count is honest either way: someone glancing at your
screen learns you have three hidden entries, not what they are.

## Marking entries you already have

For a vault with hundreds of entries, one switch at a time is not an answer.
**Tidy** — the existing review page — gained a Hidden column and proposes
entries that match a list of host names.

That list is yours. SPM ships none of its own: a built-in list would be a
maintenance burden, would be wrong for somebody, and would put the very words
this feature exists to keep off a screen into the source and into every clone
of the repository.

You supply it under **Settings → Sites to suggest hiding**, and it is stored
**inside the encrypted vault** rather than in a settings file — a plaintext
list of sites you would rather not name would leak precisely what the feature
protects. The regression suite checks that it never reaches the config
directory.

Matching is on whole hosts. An early draft split each listed host into its
labels and matched any of them, which meant a list of `.invalid` hosts had SPM
cheerfully offering to hide an unrelated admin account, because both ended in
`invalid`. A URL matches the host itself or a subdomain of it; a bare name
matches only when it is the whole host or its leading label. That case is now a
test.

Nothing is applied by the list. Tidy proposes, every row is a switch you can
turn off, and an entry you have already decided about is never proposed again.

## The format moved to 5

A record carries the flag inside its attributes column, and a 4.1.0 build
editing such a record would re-encode those attributes without it — quietly
un-hiding an entry someone deliberately hid. That is exactly what the version
row exists for: reading a format-5 vault still works on 4.1.0, and
`stamp_version` refuses to let it write one back.

`decode_attrs` now returns three values rather than two. That is a breaking
signature on purpose. Every caller unpacked two, so every caller broke at the
point of use and had to be visited — instead of quietly re-encoding a record
without a flag it never read, which is how folders and custom fields went
missing from twenty export formats until 4.1.0.

Exports carry a `hidden` column. An unrecognised value there means visible: the
safe direction for a flag nobody understood is the one that shows the entry,
not one that pretends a vault holds less than it does.

## Validation

- `python3 tests/core-test.py` — **109 tests** (was 105)
- `./tests/regression.sh` — passed, with a new block:
  `hidden: names never reach the list HTML, the Hidden section shows them, and
  the host list stays in the vault`
- Rendered in Chromium, which is where the host-matching bug showed up: the
  review offered to hide an entry that had nothing to do with the list.
- Mutation-tested. Reverting host matching to its part-wise form, dropping the
  flag on encode, and hiding regardless of the row's switch are each killed by
  the assertion written for them.
