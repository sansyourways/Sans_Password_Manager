# Sans Password Manager 5.0.2

A Dashboard navigation change, no format change — 5.0.2 reads and writes
exactly the vaults 5.0.1 does.

## What changed

The sidebar's **Records** entry now expands into a nested row per record type.
Before, every typed record lived behind a single "Records" link and you told
them apart with the type filter on the records page; now each category — SSH
keys, GPG keys, API tokens, credit cards, database and server credentials,
Wi-Fi networks, identity documents and software licences — has its own row in
the sidebar.

Each nested row carries:

- the type's own icon,
- its own name (in whatever language the Dashboard is set to),
- a count of how many entries that type holds, and
- a link straight to that filtered list.

The active category is highlighted while you are on it, and **Records** itself
still links to the full, unfiltered list.

## Why it stayed one row until now

The single "Records" row was deliberate: the point of the schema engine is
that adding a record type is a dictionary entry, not code, and a hand-written
menu with one line per type would have put that per-type work back. This
change keeps the property. The nested rows are **generated from
`RECORD_SCHEMAS`**, in the trusted core's own type order, so a new record type
appears in the sidebar on its own — no menu to edit, no row to add.

## Testing

The regression suite now asserts that the Records submenu carries a row for
every registered record type, that each row links to its filtered list and
carries its own translatable label, and that the active category is
highlighted. The accessibility checks — every control named, the sidebar
exposed as a navigation landmark — continue to pass.

## Upgrading

Nothing to do. Reinstall or redeploy the Dashboard and the sidebar shows the
nested categories. Your vault is untouched.
