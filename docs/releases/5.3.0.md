# Sans Password Manager 5.3.0

Three roadmap items in a "get the vault onto more devices and channels" cluster:
LAN device-to-device sync, QR-based pairing, and a wider set of generated package
manifests. No format change: 5.3.0 reads and writes exactly the vaults 5.2.0
does. Sync moves the already-encrypted vault file; QR and packaging never touch
it.

## What's new

### Encrypted peer-to-peer LAN sync (roadmap 45)

Sync a vault directly between two devices on the same network — offline and
server-less, like the rest of SPM. A new **`p2p`** transport joins `dir`, `rsync`
and `rclone`, reusing the existing three-way merge and conflict model unchanged:
only the **encrypted** vault file crosses the wire, so a network peer never sees
plaintext.

One device runs a listener:

```
spm sync serve            # prints a pairing string and its QR, then listens
```

`sync serve` generates a strong pairing token, detects the LAN address, prints
the `spm-sync://host:port/channel?token=…` string with its QR, and runs a
listener that is gated by the token (compared in constant time), bound to a
chosen interface (`--bind`, default all interfaces; `--port`, default 8788),
time-bounded, and validates any received vault as an SPM container before it
atomically replaces the local one — recording a security event on replace.

The other device pulls or pushes:

```
spm sync pull p2p:192.168.1.50:8788 --token <token>
spm sync push "spm-sync://192.168.1.50:8788/default?token=<token>"
```

The token comes from `--token`, the `SPM_SYNC_P2P_TOKEN` environment variable, or
a scanned pairing string. The merge, conflict and read-back-verify logic is the
same for every transport, so both devices converge on the same vault.

### QR-based device pairing (roadmap 46)

A dependency-free, pure-Python **QR encoder** (byte mode, error-correction level
M, versions 1-10, standard mask selection) renders the pairing string as a
scannable code, matching SPM's rule of leaning only on the standard library and
system tools. One encoder feeds both surfaces:

- Terminal: Unicode half-blocks. `spm qr <text>` prints any string as a QR.
- Dashboard: an SVG built from the same module matrix.

### A LAN Sync page in the dashboard

A new **Sync** page opens a bounded pairing window, shows the token as a QR and a
pairing string, and answers the same token-gated `/spm-<channel>.gpg` GET/PUT
routes the `p2p` transport speaks — so a device that scans can sync with a
LAN-bound dashboard. The routes answer only on the interface the dashboard is
bound to: a dashboard on `127.0.0.1` pairs only with the same computer, which the
page states plainly. The page is translated across all 12 locales.

### Wider packaging (roadmap 43)

Alongside the Homebrew formula and the Termux `.deb`, each release now generates
an **AUR `PKGBUILD`**, a **Scoop manifest**, and a **Nix derivation**. Each is
generated at release time and pinned to the published archive's sha256 — a
checked-in manifest would be either stale or wrong — and each is attached to the
GitHub release. All three install `spm` plus the `src/` it was built from, so an
installation can prove its own provenance.

## Compatibility

- **No format change.** 5.3.0 stays on vault format 6. The new transport, pages
  and packaging are all additive.
- **Only ciphertext crosses the network.** The `p2p` transport and the dashboard
  sync routes move the sealed container; the pairing token authenticates the peer
  and stops an unauthenticated pull.
- On its default loopback bind the dashboard's sync routes are reachable only
  from the same host; LAN pairing needs the server bound to a LAN address.

## Testing

The core suite gained QR encode tests that decode back through `zbarimg` across
every version 1-10 (guarded, skipped where the tool is absent) plus structural
invariants, and a `sync-serve` loopback test that serves a vault to the right
token, refuses the wrong one, and replaces the vault only from a valid container.
The shell suite exercises the `p2p` transport end to end against a real listener
— status, a pairing string, a wrong or missing token refused, and a push that
lands only ciphertext — and the packaging block covers the AUR, Scoop and Nix
generators (structure, version, checksum, determinism, and refusal of a bad
version or sha). The Dashboard suite covers the Sync page's pairing string and
QR, the new sidebar entry, and accessibility for its controls.

## Upgrading

Nothing to do. Reinstall or redeploy the Dashboard. Your vault is untouched. LAN
sync is opt-in: nothing listens until you run `spm sync serve` or open a pairing
window on the dashboard.
