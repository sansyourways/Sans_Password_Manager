# Sans Password Manager 5.0.3

A Dashboard navigation option, no format change — 5.0.3 reads and writes
exactly the vaults 5.0.2 does.

## What changed

5.0.2 gave every record type its own nested row under **Records** in the
sidebar, always visible. Some people want that; others would rather keep the
sidebar short and open the categories only when they need them. 5.0.3 makes it
a choice.

- **The default is unchanged.** Out of the box the sidebar still shows each
  record category as its own row nested under Records — SSH keys, GPG keys, API
  tokens, credit cards, database and server credentials, Wi-Fi networks,
  identity documents and software licences — each with its icon, name and count.
- **A one-click Settings toggle folds them away.** Turn on *"Collapse record
  categories into an expandable Records menu"* in Settings and **Records**
  becomes a disclosure: the categories stay hidden until you click Records,
  which expands an **All** row followed by one row per type. Clicking again
  collapses it.

The active category is highlighted in both layouts, and **Records** always
reaches the full, unfiltered list — as a link in the default layout, and as the
**All** row when collapsed.

## How the preference is stored

The choice lives in the browser (`localStorage`), like the theme and idle-lock
preferences, so it is per-device and never leaves the machine. It is applied by
a tiny inline script before the first paint, so the sidebar renders in your
chosen layout immediately — no flash of the other one, and no dependence on the
main script having loaded.

## Why both layouts stay schema-driven

The point of the schema engine is that adding a record type is a dictionary
entry, not code. Both the always-visible rows and the collapsible submenu are
**generated from `RECORD_SCHEMAS`**, in the trusted core's own type order, so a
new record type appears in whichever layout you have chosen with no menu to
edit.

## Testing

The regression suite now asserts that both layouts are served — the
always-visible Records link and its rows, and the collapsible toggle with its
`All` row and per-type rows — that the Settings page carries the layout toggle,
and that a row exists for every registered record type in each. The
accessibility checks — every control named, the sidebar exposed as a navigation
landmark, the disclosure button carrying `aria-expanded`/`aria-controls` —
continue to pass.

## Upgrading

Nothing to do. Reinstall or redeploy the Dashboard; the default sidebar is
unchanged, and the new layout is one toggle away in Settings. Your vault is
untouched.
