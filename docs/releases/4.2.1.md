# Sans Password Manager 4.2.1

The Security page told you something was wrong and gave you no way to act on
it. This fixes that.

## What it looked like

```text
Weak passwords
Shorter than 12 characters, or using fewer than three character classes.

  8    26   29   31   45   49   53   64   71   77
  84   95  102  103  107  126  150  171  191
 198  204  223  232  238  243  245
```

Those are record ids. Acting on the report meant cross-referencing thirty-odd
numbers against the password list one at a time. Above it sat a red `0` with no
scale and no explanation.

## What it looks like now

Every finding names the entry, shows its username, and carries the single
action that clears it:

```text
Weak passwords
Shorter than 12 characters, or using fewer than three character classes.
4 entries

  1   Acme Admin    avery@example.invalid    View  [ Change password ]
  2   Mail Relay    ops@example.invalid      View  [ Change password ]
  5   ••••••••      ••••••••                 View  [ Change password ]
```

`Change password`, `Add the details` and `Fix this entry` each link straight to
that entry's form.

The score is a fraction, and it says what drove it:

```text
9 / 100   Security score
4 weak · 2 reused · 5 aging · 1 incomplete
```

Each of those links to the section it counts. The number on its own could not
tell a slightly poor vault from a very poor one — the penalty is capped, so
one weak password too many and a hundred of them both read `0`.

Reused passwords are groups now, with a count and a line saying what actually
clears the finding: change all but one.

## The line that had to hold

The old page rendered ids on the reasoning that it stays safe to open in
public. Half of that reasoning is right and half is not: a **secret** must
never appear, but a service name is already on every other page of the
dashboard.

The exception is a hidden entry. Naming entries here would have made this page
the one place a hidden name could be read, so hidden entries stay redacted on
the Security page exactly as they are in the password list. The regression
suite asserts it directly, with a fixture entry that is both weak and hidden.

## Two bugs found by rendering it

Neither would have failed a test of the function underneath.

- **The catalogue wins over inline text.** Rewording a hint in the HTML does
  nothing when the element carries a `data-i18n` key — the twelve catalogues
  hold the real string. Two reworded hints rendered as their old selves until
  the catalogues were updated too.
- **The tally's singular/plural branch was dead code.** `data-i18n` replaces an
  element's whole text, so whichever form the catalogue holds renders at every
  count, and the page said "1 missing details". The words are count-neutral
  now — `1 incomplete`, `4 incomplete` — which also spares eleven languages a
  plural rule they do not share.

## Validation

- `./tests/regression.sh` — passed, with a new block: `security: findings are
  named and actionable, and a hidden entry stays redacted`
- `python3 tests/core-test.py` — 109 tests
- Rendered in Chromium at every step; both bugs above came from looking at the
  output rather than from an assertion.
