# Sans Password Manager 3.6.0

An accessibility pass over the dashboard, which also found a shipped bug.

## The audit

Every one of the eleven dashboard pages was walked through Chrome's real
accessibility tree rather than read as source. Fifty-two issues, none of them
visible by looking at the code, all of them visible to anyone using a screen
reader:

| | Before | After |
|---|---:|---:|
| Inputs with no label association | 22 | 0 |
| Controls with no accessible name | 19 | 0 |
| Pages with no navigation landmark | 11 | 0 |
| Tables with no header cells | 1 | 0 |

One cause covered most of it. Forms rendered `<label>Service</label>` followed
by an input with no `id`, so the label was attached to nothing. It looked
correct on screen and read as loose text somewhere near a field that announced
itself as "edit text, blank". Every form goes through one helper, so the fix
went there.

## The focus ring was invisible

`.input:focus` removed the outline and replaced it with a `box-shadow` in
`--accent-soft`. On the Console palette that is `#10251a` against a `#0f1412`
field: **1.15:1**.

WCAG 1.4.11 asks for 3.0:1 on a non-text indicator. The ring existed in the DOM
and could not be seen, on every form in the dashboard, for anyone navigating by
keyboard. It is now `--accent`, measured at 9.7:1, and the suite fails if that
ratio ever drops below 3.0 again.

## A bug 3.4.3 shipped

The Bitwarden import options were attached to the **export** dropdown:

```
form action=/export   select id=import-fmt   offers Bitwarden: True
form action=/import   select id=(none)       offers Bitwarden: False
```

The feature could not be chosen from the picker. It worked at all only because
the format is auto-detected when plain `json` or `csv` is selected — a safety
net that happened to hide the fault.

The reason it shipped is the same reason 3.4.2's banner shipped: the tests
called the import function directly and never rendered the page. The new
assertions are made against rendered markup, which is the only place this class
of defect exists.

Four translation keys were also referenced in the markup while present in no
dictionary, so they rendered as English in every language. Three of them were
added with that same Bitwarden UI.

## What the new tests cover

- No unnamed control on any form
- The sidebar is a navigation landmark
- The focus ring's contrast, computed
- The Bitwarden entries are on the import form, and not on the export form
- Every `data-i18n` key used in the markup exists in the dictionary

That last one closes a real blind spot. The parity check added in 3.3.0
compares the three dictionaries against each other, so a key missing from all
three is perfectly consistent and invisible to it. Both failure modes are now
caught, by different assertions.

## Upgrade and compatibility

No vault-format migration, no behaviour change to any command. This release
changes markup, one CSS rule and the test suite.

## Verification

- Generated `spm.sh` reproduced from `src/`
- Full disposable-vault regression suite passes
- The audit re-run after the fixes reports zero issues across all eleven pages
- Keyboard walk confirms the skip link is the first stop, tab order follows
  reading order, and every stop shows a visible ring
- Five mutations caught: unlabelled fields, the sidebar as a plain div,
  Bitwarden back on the export form, the invisible focus ring restored, and a
  dictionary key removed
