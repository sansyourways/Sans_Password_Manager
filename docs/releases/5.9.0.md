# Sans Password Manager 5.9.0

Three high-priority enhancements from the audit backlog, shipped together. No
vault format change, and existing vaults are untouched.

## Move a stored TOTP to another app with a QR

A one-time-code secret kept in SPM can now be handed to a phone authenticator
without retyping the base32 secret. `spm authenticator-qr <id>` prints a
scannable QR alongside the `otpauth://` URI, and the Dashboard's authenticator
view gains a **Show QR** reveal.

Because the QR encodes the raw shared secret, it is treated like the secret
itself: it is revealed only on demand, served only to the unlocked session, and
never rendered into the page up front. The QR round-trips through the same
`otpauth://` parser SPM uses on import, so a scanned code matches the one SPM
shows.

## Dedicated importers for LastPass, Chrome/Edge and 1Password

The Export / Import page already read Bitwarden's three export files directly.
It now reads three more managers' CSV exports the same way:

- **LastPass** — logins, secure notes (kept as notes) and folders; a stored TOTP
  becomes an authenticator.
- **Chrome / Edge** — the `name,url,username,password[,note]` password CSV.
- **1Password** — logins with tags and notes; a `OTPAuth` field becomes an
  authenticator.

Each is offered explicitly in the picker, and a file chosen as plain CSV is
autodetected — so a wrong dropdown choice is a correct import rather than a
silent partial one. As with the Bitwarden importers these are import-only, and
the field mapping lives in the shared core, so the CLI and the Dashboard read a
given export identically. TOTP secrets, folders, tags and notes are carried
across rather than dropped.

## On-device 2FA-availability audit

The security review can now point out accounts you could protect with two-factor
authentication but have not. It flags password records whose service is on a
bundled list of 2FA-supporting domains and that have no matching authenticator
in the vault.

- CLI: `spm security --twofa`
- Dashboard: **Check for missing 2FA** on the Security page

The check runs entirely on-device against a small bundled list — extendable with
a `SPM_TWOFA_DOMAINS` file — and no account identifier or any other data leaves
the device.

## Upgrading

Reinstall or redeploy. Nothing about how vaults are written changes.
