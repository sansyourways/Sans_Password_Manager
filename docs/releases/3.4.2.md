# Sans Password Manager 3.4.2

`doctor --json` did not work as a command. This fixes it, and fixes the reason
it was not caught.

## What was wrong

3.4.0 added `spm doctor --json` with one promise: stdout carries a JSON
document and nothing else, so it pipes into `jq` without a filter.

Run as an actual command, it emitted the SPM banner, then a `Master password: `
prompt, and only then the document — if it got that far. The first byte of
stdout was an ANSI escape sequence.

## Why the tests passed

They called `cmd_doctor_json` after sourcing the library. That skips `main()`
entirely, and `main()` is where the banner, the language prompt and the consent
gate are. The function was correct the whole time. The command was never
exercised.

That is the more useful half of this release: a test that sources a shell
script and calls one of its functions is testing a function, not a program.
Where the contract is about what a program writes to stdout, only running the
program can check it.

## The fix

`doctor --json` now dispatches before `ensure_requirements`, `choose_language`
and `ensure_policy_consent` — exactly as `bridge-get` and `bridge-list` already
did, for exactly this reason. Those had a comment saying a machine-readable
protocol must never emit prompts before its response; `doctor --json` is the
same kind of contract and should have joined them when it was written.

The master-password prompt also moved from stdout to stderr. Prompts belong
there: an interactive user sees no difference, because stderr is the same
terminal, and no command's stdout can be polluted by it again.

## The test

The suite now runs the real command with a password on stdin and asserts:

- the **first byte** of stdout is `{` — not merely that the output parses,
  because a JSON parser skips leading whitespace and would accept a banner
  that ends in a newline
- the banner string does not appear on stdout
- no password prompt appears on stdout
- the prompt *does* appear on stderr, so it did not simply vanish
- the exit status follows the verdict

Reverting the dispatch fix reproduces the shipped bug and the test catches it.

## Upgrade and compatibility

No vault-format migration. Anyone scripting against `doctor --json` from 3.4.0
or 3.4.1 was receiving a banner; this is the release where that stops.

## Verification

- Generated `spm.sh` reproduced from `src/`
- Full disposable-vault regression suite passes
- `spm doctor --json` against a disposable vault: stdout begins `{`, parses as
  one document, prompt on stderr
- Two mutations caught: removing the early dispatch, which is precisely the
  3.4.1 defect, and returning the prompt to stdout
