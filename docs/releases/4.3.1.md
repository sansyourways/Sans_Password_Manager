# Sans Password Manager 4.3.1

Two sentences that stopped being true in 4.0.0.

The login page said:

```text
All decryption happens locally with GnuPG. Nothing leaves this host.
```

and the password list said:

```text
Passwords are never sent anywhere else – all crypto stays on this host with GnuPG.
```

Neither has been true of a current vault since 4.0.0, which seals with
AES-256-CTR under an HMAC-SHA256 tag and uses gpg only to read vaults written
before it. 4.0.0 corrected exactly this claim on the overview console — *"GnuPG
boundary active on this host"* — and missed these two, which sit on the two
pages people see most.

Both are tool-neutral now:

```text
All decryption happens on this host. Nothing leaves it.
Passwords are never sent anywhere else – all crypto stays on this host.
```

That is the actual fix. Naming the cipher is what made these sentences go stale
when the backend changed; the claim that matters — it happens here, nothing
leaves — is true of every vault format SPM has ever written and will survive
the next change too.

Found while looking at a screenshot of the login page for the 4.3.0
documentation refresh. Publishing a picture of the wrong claim is a slower way
to find it.
