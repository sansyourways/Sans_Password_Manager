# Sans Password Manager 3.4.1

One fix: the CLI takes a vault lock on macOS, which it never has.

## What was wrong

SPM's advisory vault lock was `flock(1)`. That is a util-linux program, and
macOS does not ship it. `acquire_cli_vault_lock` checked for it, printed a
warning when it was missing, and continued without a lock.

The SPM Dashboard, meanwhile, has always locked through Python's `fcntl.flock`,
which exists everywhere. So on macOS the dashboard was locking and the CLI was
not — which is worse than neither locking, because one side believed it was
protected while the other walked straight through it.

The consequence is a lost update: a CLI write and a dashboard write that
overlap, and one of them disappears. Measured on Linux by removing the lock
from five concurrent writers, one record survived out of five.

## The fix

Where `flock(1)` exists, nothing changes. Where it does not, the CLI takes the
same lock through `python3 -c 'import fcntl; fcntl.flock(9, fcntl.LOCK_EX)'`.
python3 is already a hard dependency, and this is the primitive the dashboard
already uses on the same file, so the two genuinely exclude each other — which
was the whole point and is not something a different locking scheme would have
given us.

The lock is taken on file descriptor 9, which the shell holds open for the
duration. The helper process exiting does not release it: the lock belongs to
the open file description, and the shell still holds a descriptor for it.

**There is no stale lock to detect.** The kernel drops the lock when the last
descriptor referring to it closes, and that includes the holder being killed.
`mkdir` is the usual portable answer and would have been the wrong one here: it
would have needed a PID file, a liveness check, and a story for PID reuse, all
to approximate something the kernel already does correctly.

## Testing it where it does not apply

A fallback that only runs on macOS is a fallback that runs almost nowhere. The
regression suite now hides `flock(1)` behind a PATH containing only the tools
the test needs, so the Python path is exercised on every platform, and it
refuses to run at all if it fails to hide `flock` — a test that silently
measured the wrong path would be worse than no test.

## Upgrade and compatibility

No vault-format migration, no configuration change. Vaults, recovery material,
CLI commands, the dashboard and the browser extension are unchanged from 3.4.0.

## Verification

- Generated `spm.sh` reproduced from `src/`
- Full disposable-vault regression suite passes
- With `flock` hidden, eight racing writers through the real
  `acquire_cli_vault_lock` produce eight increments; six racers through the
  actual shipped function produce six
- A CLI holder blocks a dashboard-style `fcntl` acquirer on the same file,
  confirming the two are mutually exclusive rather than merely both "locked"
- Kernel release confirmed directly: a `SIGKILL`ed holder with no surviving
  children leaves the lock free
- Two mutations caught, each with the pre-3.4.1 symptom of 1 of 8 surviving:
  taking no lock at all, and taking a shared lock instead of an exclusive one
