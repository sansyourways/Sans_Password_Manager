# Sans Password Manager 3.7.1

Documentation only.

`spm.sh` is byte-identical to 3.7.0 apart from its version string — the diff is
one line — so there is nothing here that needs installing. This release exists
so the roadmap that describes 3.3.0 through 3.7.0 travels inside the archive
alongside the code it describes, rather than only on the default branch.

## What changed

`ROADMAP.md` records what shipped across those releases: `doctor --json`, the
dashboard session-key cache, fault injection and cross-platform coverage in
3.4.0; the portable vault lock in 3.4.1; Bitwarden imports in 3.4.3;
per-record password history in 3.5.0; the dashboard accessibility pass in
3.6.0; and the extension boundary in 3.7.0.

Two items remain open, and the roadmap now says plainly that neither is waiting
on effort. The in-field picker needs a browser's extension UI driven for real,
and hardware-backed key wrapping needs a FIDO2 key or a TPM to test against.

That distinction earned a section because of what those releases showed. Five
defects reached a release and were found only when something was rendered or
executed rather than unit-tested:

- a translation dictionary that failed to parse, so the language picker had
  never worked in any version that carried the string
- `doctor --json` emitting a banner and a password prompt ahead of its document
- the Bitwarden import formats attached to the export dropdown, leaving the
  feature unreachable from the picker
- a focus ring present in the DOM at 1.15:1 against the field it surrounded
- an error path that stringified a filesystem path instead of refusing it

Each had passed a test of the function underneath it. Crypto and extension UI
are the two worst places to accept that gap, which is why those two items wait
for a way to run them rather than for someone to write them.

`docs/BROWSER-EXTENSION-ROADMAP.md` no longer names target versions for phases
that have not started. It named one four times and was wrong within a day each
time: 3.3.0 went to the dashboard's dead controls, 3.4.0 to diagnostics, 3.5.0
to per-record history — none of them that plan. The order is the part worth
trusting; the version each phase lands in is decided when it is ready.

## Upgrade

There is nothing to upgrade. If you are on 3.7.0 the program is the same
program. Take this release if you want the current roadmap in the archive.
