# Sans Password Manager 3.7.0

The extension's boundary is now a contract it cannot talk past.

## What was there before

The native-messaging host validated what came *in*: four actions, a hostname
matched against a pattern, a record id that had to be digits, and no way for a
message to choose which SPM command ran — each branch names a literal `bridge-*`
command. That half was sound.

Going *out*, it forwarded whatever the CLI printed. `bridge-get` prints a
username and a password, so that is what the extension received. Which means
the extension's view of the vault was not a contract at all — it was whatever
`bridge-get` happened to emit that release. Add a field there for the
dashboard's benefit and it reaches the extension with no code change, no
review, and nothing to notice it.

## What it is now

Responses are projected onto the fields each action declares:

| Action | Returns |
|---|---|
| `unlock` | `ok` only — the verdict, not the list used to reach it |
| `lock` | `ok` |
| `list` | `matches`, each row reduced to `id`, `label`, `username`, `url` |
| `get` | `username`, `password` |

A `list` match is a record summary, and summaries are exactly where an extra
field would appear, so each row is reduced as well. A password appearing in a
match cannot cross.

Adding a field to what the extension can see now requires editing that table,
which is the review the boundary exists to force.

## Errors

Failures are chosen from a fixed set rather than echoed.

The first version of this stringified unexpected errors, which felt sufficient
and was not: it changed the *type* while the content still crossed. An error of
`gpg: /home/you/.spm_vault.gpg: decryption failed` still carries a filesystem
path over a boundary whose whole purpose is that nothing crosses unnamed. Every
message the CLI's bridge commands and the host itself can produce is now
enumerated; anything else becomes a generic refusal.

## What the boundary does not do

The original one-shot extension, still in this repository, sends the master
password with every `get` and holds no session. That path is kept, because
removing it would break that extension silently — but it is not constrained by
**Lock** or by either timeout. A caller supplying the password directly has no
session for those to act on. That is a property of a one-shot protocol rather
than a hole the table can close, and it is now written down in the extension's
README instead of sitting as a quiet exception in the code.

The popup in `browser-extension-universal/` never sends the master password
except to `unlock`.

## Upgrade and compatibility

No vault-format migration. The extension protocol is unchanged in shape: the
fields the popup already reads are exactly the fields still returned. Nothing
needs reinstalling beyond the usual native-host refresh.

## Verification

- Generated `spm.sh` reproduced from `src/`
- Full disposable-vault regression suite passes
- The host driven over real native messaging end to end: unlock, list, get and
  an unknown action, with the note field absent from every response and the
  password present where it should be
- Three mutations caught: forwarding the response instead of projecting it,
  echoing an error instead of allowlisting it, and letting match rows through
  unprojected — each reported with the exact field that escaped
