## Upgrading

Safe and uneventful. No vault format change, no migration, no command changed.
If you are already on 3.0.0 your vault is untouched by this release.

If you are coming from 2.13.0 or earlier, read
[the 3.0.0 notes](3.0.0.md) first — that release changed the vault format in a
way you cannot reverse by reinstalling an older version, and it asks you to
back up your vault and `.recovery` file before upgrading. That advice still
stands; this release does not change it.

## Fixed

**Sourcing `spm.sh` no longer runs it.**

The script ended in a bare `main "$@"`, so `source spm.sh` — the ordinary way
to reach one of its functions from a test or a helper script — fell straight
into the interactive menu.

That is worse than it sounds. A menu blocked on `read` keeps whatever it has
already acquired, and that includes an exclusive `flock` on
`${VAULT_FILE}.lock`. For a caller that had not set `PASSWORD_VAULT`,
`VAULT_FILE` resolves to `~/.spm_vault.gpg` — the real vault. A sourced helper
could therefore sit on a live vault's lock indefinitely and block every write
to it, with nothing on screen to say why. One was found holding a lock for
fourteen hours.

`main` now runs only when the file is executed:

```bash
if [ "${BASH_SOURCE[0]:-$0}" = "$0" ]; then
	main "$@"
fi
```

The `:-$0` default is load-bearing rather than decorative. Piped into a shell
there is no `BASH_SOURCE` at all, and under `set -o nounset` a bare reference
aborts with `unbound variable` instead of running — which would have broken
`curl … | bash` for a guard whose only job is telling sourcing apart from
execution. It was written without the default first, and the regression suite
now asserts every one of these paths: sourcing is inert, executing dispatches,
and piping dispatches.

Nothing in the shipped product sourced `spm.sh`, so no user-facing behaviour
changed. The CLI, the SPM Dashboard, the browser bridge and `install.sh` all
reach the script the same way they always did.

## Changed

The regression suite had been working around the missing guard by sourcing a
copy of the script with its last line stripped by `sed '$d'` — correct only for
as long as `main "$@"` remained the literal final line, and silently wrong the
day anything followed it. It sources the script directly now.

It also asserts its own isolation immediately after sourcing: `VAULT_FILE` must
resolve inside the disposable test root. It always did — `HOME`, the XDG paths,
`PASSWORD_VAULT` and `GNUPGHOME` are all redirected there — but the failure
mode is a locked live vault rather than a failing test, so it is worth
asserting rather than assuming.

A review pass over the new tests found five defects in them, all fixed here:
the isolation check exited before the harness cleanup trap was restored, so
firing it would have leaked the disposable root and its `gpg-agent`; the
sourcing probe blamed the entry-point guard for any non-zero status, including
an ordinary syntax error; the execution check asserted the banner text but not
the exit status; the "piped to a shell" check used a redirect from a file,
which is seekable and therefore not the code path `curl … | bash` takes; and
the library path, having moved out of `mktemp` and into the checkout, was
interpolated into a `bash -c` string without quoting.

## Verification

`./build.sh --check`, `bash -n`, `shellcheck -x -S warning`, `compileall` over
the trusted core and the dashboard, and the full regression suite pass on
Ubuntu, macOS and in the official Termux container.

The new tests are mutation-checked in both directions: with the guard removed
sourcing blocks and the probe times out; with the `:-$0` default removed the
piped invocation aborts on an unbound variable. Both mutations were applied and
confirmed to fail the suite for the right reason before the fix was accepted.
