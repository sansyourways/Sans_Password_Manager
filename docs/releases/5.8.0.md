# Sans Password Manager 5.8.0

Argon2id as a capability-gated key-derivation option — roadmap item 3, the last
item that had stayed blocked. No vault format change.

## Why this was blocked, and what changed

Argon2id is the memory-hard KDF the roadmap named as scrypt's eventual
successor. It stayed unshipped because no runtime SPM targets provides it
without a third-party dependency: `hashlib` has scrypt and PBKDF2 but no Argon2,
Argon2 arrived in **OpenSSL 3.2** while current Debian/Ubuntu ship OpenSSL 3.0
(and macOS ships LibreSSL with no `openssl kdf` at all), and GnuPG cannot express
Argon2id for symmetric messages. SPM's portability rule ruled out taking a
dependency to get it.

5.8.0 resolves that by making Argon2id **capability-gated**: it is used only
where a backend is already present that keeps the master password **off the
argument vector** — the **argon2 reference CLI** (which reads the password on
stdin) or the **argon2-cffi** module (which never leaves the process). scrypt
(n=65536, 64 MiB) stays the default, because it is reachable everywhere.

`openssl kdf` is deliberately **not** used as a backend: it accepts the password
only as a `-kdfopt pass:` argv value that `ps` can read, and no key-derivation
path in SPM has ever put a password there.

## Using it

```
spm kdf status      # show this vault's KDF, and whether a backend is installed
spm kdf argon2id    # rewrap this vault to Argon2id (needs a backend)
spm kdf scrypt      # rewrap back to scrypt (opens on any SPM)
```

Install a backend with `apt install argon2` (or your platform's package) or
`pip install argon2-cffi`. `doctor` reports the vault's KDF and warns if an
Argon2id vault is opened where no backend exists.

Switching KDFs rewraps only the master-password envelope — the vault key and the
vault ciphertext do not change — so a switch costs one rewrap, not a
re-encryption, and the recovery file, `.bak`, history and synced copies still
open under the same master password.

## How it fits the format

No format bump. Format 6 already recorded the KDF **by name and parameter**, and
the reader derives with the vault's own numbers. Argon2id is a new name
(`argon2id`) with its own parameters (`m`, `t`, `p`) on that same line — a value
the reader dispatches on, exactly what recording the KDF by name was for.

## Safety properties

- An Argon2id vault carried to a machine **without a backend** refuses to open
  with a message that names the fix, never a wrong-password error.
- Choosing Argon2id is refused **up front** on a machine that could not reopen
  the result, so no vault is written that its own machine cannot read.
- A missing backend never causes a silent fall back to scrypt, and never puts
  the password on argv.

## Upgrading

Reinstall or redeploy as usual. Existing vaults are untouched and stay on
scrypt; opting into Argon2id is a deliberate `spm kdf argon2id`. Your vault key
and contents do not change.
