# Sans Password Manager 3.12.1

The remaining Phase 2 security-review work is complete: duplicate analysis
stays local, and known breach review is available as an explicit opt-in.

## Opt-in breach review

Run:

```bash
spm security --breaches
```

Or open **Security** in the SPM Dashboard and choose **Check known breaches**.

SPM computes each password's SHA-1 hash locally and sends only its first five
hexadecimal characters to the Pwned Passwords range API. Full hashes and
passwords never leave the device. Responses are padded, compared locally, and
discarded; only affected record IDs and occurrence counts are shown. Requests
are bounded to four in flight so a large vault cannot create unbounded fan-out.

The default security report remains completely offline. If the optional
service is unavailable, SPM reports that the check was unavailable rather than
showing a false clean result.

## One report, two clients

CLI and Dashboard now consume the same trusted-core security report. This
removes the duplicated scoring code that had drifted previously while keeping
passwords, fingerprints, and hashes out of rendered output.

## Compatibility

No vault-format change and no migration. Rolling back to 3.12.0 leaves every
vault readable; only the optional breach-review capability is absent.
