# Sans Password Manager 5.10.0

Three security-review and audit-log enhancements from the backlog, shipped
together. No vault format change, and existing vaults are untouched.

## Insecure-URL (http) report

Autofill is already refused on plain `http://` pages. The security review now
names the stored password entries that carry such a URL, so they can be moved to
`https` rather than sitting where a credential would travel in the clear. It runs
on-device on every review — no flag — and appears on both `spm security` and the
Dashboard's Security page.

## Weak-PIN and weak-code detection

The review scored passwords but ignored the PINs on card and other typed
records. It now flags a PIN that is trivially weak — a single repeated digit, a
sequential run like `1234`, or one of the most-guessed codes — while never
printing the value itself. The check is deliberately conservative: only a short
all-digit field is ever considered, so a long account number or a random code is
never a false positive.

## Tamper-evident event log

The security-event log records unlocks, writes and master-password changes. It
lives in plaintext beside the vault — deliberately, because a failed unlock is
the event you most want and cannot be written into a vault nobody can open.

Each line is now **chained to the one before it** with an HMAC-SHA256 keyed by a
per-vault key in a `0600` sibling file. `spm events --verify` — and an integrity
badge on the Dashboard's Security Events page — recompute the chain and report
the first entry that fails, so an edit, insertion, reordering or deletion is
detected rather than silent. A legitimate prune of the oldest entries re-anchors
the chain rather than breaking it.

The honest limit: the log is plaintext, so an attacker with full local read of
the key file can still forge it — but that is the same access that already lets
them read the vault file sitting next to it. The chain defeats naive edits,
deletions and truncation by anything without the key.

## Upgrading

Reinstall or redeploy. Nothing about how vaults are written changes. The
event-log chain begins at the first entry written by 5.10.0; entries recorded by
an earlier version carry no MAC and re-anchor the chain rather than failing it.
