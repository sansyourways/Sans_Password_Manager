# Sans Password Manager 5.7.0

The six partial roadmap items completed, plus first-class browser-extension
installation. No format change: 5.7.0 reads and writes exactly the vaults 5.6.0
does.

## What's new

### Machine-readable CLI output (roadmap 47)

`spm list --json` prints every password as JSON — id, service, username, url,
created, and the folder and state flags — and never a secret. `spm get <id>
--json` prints one record including its password (the same reveal `get` already
gives a person), with no clipboard countdown. Together with the existing `doctor
--json`, `events --json` and `expiring --json`, scripts can now read the vault
without scraping tables.

### Per-record password expiration (roadmap 29)

A vault has one rotation window (`SPM_ROTATION_DAYS`); now a single record can
override it:

```
spm rotation set 42 90      # this login rotates every 90 days
spm rotation set 7 never    # a lifelong code that should not age
spm rotation clear 42       # back to the vault default
spm rotation list
```

The override lives in the record's attributes and feeds the same aging check the
security score reads.

### Advanced search grammar (roadmap 27)

The Dashboard search box understands structured operators, combinable with free
text:

- `type:ssh-key`, `type:password`, `type:note`, … — restrict to a kind/type
- `tag:work` or `#work` — a hashtag (in notes or fields) or a matching folder
- `folder:Personal` — restrict to a folder
- `is:favorite`, `is:hidden`
- `expires:<30d`, `expires:overdue`, `expires:<2026-12-31` — dated records

A plain query with no operator takes the exact substring path it always did.

### Enhanced form matching (roadmap 51)

The extension reads a field's own hints — `name`, `id`, `autocomplete`,
`placeholder`, `aria-label` — as well as the company it keeps, so it recognises:

- **username / email** fields even on a two-step login whose first page has no
  password box,
- **new and confirm password** fields (the generator fills both), and
- **one-time-code** fields — and offers to **fill the current TOTP** for a
  matching authenticator, through a new `totp` bridge action that returns the six
  digits and their lifetime, never the seed.

### Hardware-backed recovery (roadmap 2)

Reset the master password with a **registered security key**. The vault key is
recovered from the same PRF-sealed envelope that has opened the vault without a
master since 4.8.0, then the key envelope is rewrapped under a new master — with
**no RSA recovery file in the path**. The Dashboard unlock page offers *"Reset
master with a security key"*; it is pre-auth and rate-limited, because a lost
master is exactly when it is needed.

TPM and Secure Enclave remain out of reach on SPM's bash-and-Python terms (like
Argon2id); a FIDO2 security key is the hardware SPM can genuinely reach, and this
brings it to recovery.

### Emergency-access time-lock (roadmap 5)

A recipient holds an emergency kit offline, so a delay cannot be enforced by a
clock they control — but **work** can. With `--delay-hours`, the kit's payload is
sealed behind a sequential-squaring time-lock puzzle (Rivest-Shamir-Wagner):

```
spm emergency-create 42 recipient.pub 2026-12-31 kit.tgz --delay-hours 24
```

The owner seals it cheaply (they know the modulus factors); the recipient must do
the squarings in order — no shortcut, no parallelism — so they cannot open it
early. Wall-clock depends on the recipient's hardware, so the delay is a floor,
not a promise, which the kit says plainly. Kit creation is recorded in the
security-event log (`spm events`). A kit created without a delay is byte-for-byte
what earlier versions produced.

A hard *cancellation* of an offline, self-contained kit is not achievable without
the infrastructure SPM avoids; the enforced delay is the owner's window to rotate
the shared credential, and the audit log is the record that a kit exists.

### Browser-extension installation, first-class

Installing the extension is now one obvious step wherever you are:

- **CLI:** `spm extension setup` (guided, Linux/macOS), `spm extension host
  <id>` (register just the native host), `spm extension manual` (step-by-step
  manual instructions for any platform), `spm extension path`.
- **Interactive menu:** a new *"Browser extension setup"* entry.
- **Dashboard:** a **Browser extension** page with the guided and manual steps.

## Compatibility

- **No format change.** 5.7.0 stays on vault format 6.
- **Everything is additive and opt-in.** The JSON flags, per-record rotation, the
  search operators, the security-key reset, and the emergency time-lock are all
  there when you use them and invisible when you do not.

## Testing

The core suite gained tests for per-record rotation, the search-query parser, the
TOTP computation and bridge match, the hardware master-reset (reset succeeds; the
old master, a wrong PRF secret, an unknown credential and an empty new master are
all refused), and the time-lock (seal-and-open round trip). The native-host
regression projects the `totp` action to the digits and their lifetime and
refuses it when locked. The shell suite exercises `list`/`get --json`,
`rotation`, and `spm extension`.

## Upgrading

Nothing to do. Reinstall or redeploy the Dashboard; your vault is untouched. The
new commands and the extension setup page are all opt-in.
