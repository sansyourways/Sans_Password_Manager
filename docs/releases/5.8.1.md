# Sans Password Manager 5.8.1

A hardening fix found by auditing the 5.8.0 Argon2id work. No vault format
change, and existing vaults are untouched.

## What changed

**The Argon2id cost parameters read from a vault header are now bounded.**

The vault's `KDF` line is unauthenticated by design: it is read to derive the
key that then verifies the vault's MAC, so its parameters are processed *before*
authentication can fail. scrypt has always been safe here because it derives
under a fixed `maxmem`, so a tampered `KDF scrypt n=<huge>` line fails closed
with a memory-limit error rather than trying to reserve the memory.

Argon2id, added in 5.8.0, had no equivalent bound. A tampered
`KDF argon2id m=<huge>` line would flow straight to the argon2-cffi backend,
which reserves `memory_cost` kibibytes with no timeout — enough to OOM the
process on open. This is the kind of tampered-vault input SPM's authentication
is meant to catch, but the KDF parameters are read ahead of that check.

5.8.1 bounds them, the same way scrypt is bounded: memory above **1 GiB**, or a
time or parallelism cost outside **1..16**, is refused before a byte is
reserved. SPM's own defaults (64 MiB, t=3, p=1) sit well inside the range, so no
real vault is affected. As a smaller defense-in-depth fix, an Argon2id salt that
is not argv-safe (one beginning with `-`) is refused on the CLI backend rather
than left for the `argon2` command to read as an option.

## Upgrading

Reinstall or redeploy. Your vault is untouched, and nothing about how vaults are
written changes.
