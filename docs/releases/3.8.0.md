# Sans Password Manager 3.8.0

An import is now reviewed before it is written.

Until this release, uploading an export in web mode committed it. The first
sight of what a Bitwarden file actually contained was the vault already
containing it. 3.4.3 made that sharper rather than answering it: Bitwarden
exports began importing correctly and went straight in, and the failure it
replaced — a CSV that produced one empty note and silently dropped every login
while the dashboard reported success — is exactly the kind a review would have
shown first.

## What you see

Upload a file as before. Instead of a redirect, the page now shows what the
file would add: each record's type, service, username, and its secret masked
behind the same reveal control the rest of the dashboard uses. Rows SPM has no
record type for are listed by name above the table, so nothing disappears
without being named.

Nothing has been written at that point. **Import these records** commits it;
**Cancel** leaves the vault exactly as it was.

## Two decisions worth stating

**The parsed rows stay on the server.** Sending them to the browser for the
confirm step would have been simpler and is what a hidden form field invites,
but it would hand a decrypted password-protected export back to the page that
uploaded it — strictly worse than today, where the decrypted form never leaves
the server. The review is held in the session record instead, beside the
cached vault key, and dies with the session. It also expires after five
minutes: a review left open over lunch should not still be committable.

**The confirmation is single-use.** A refresh, a back button, or a re-sent form
must not import the same file twice, so the held review is consumed on the
first attempt whether or not the token matched.

**The preview and the commit share one classification.** The commit does not
re-read the file; it applies the rows the review displayed. A preview that
counts a row the commit then drops is the specific failure a preview exists to
catch, and it cannot happen if there is only one reading.

## What is not in this

The review says what will happen. It does not let you deselect rows or edit
them — correcting an export is still done in the file. That is a smaller
feature than "inspected and corrected" on the roadmap, and the roadmap now says
so rather than claiming otherwise.

The CLI `spm import` is unchanged and still writes in one step.

## Compatibility

`POST /import` with an upload now answers HTTP 200 with the review page rather
than redirecting. A caller sending `X-Requested-With: fetch` gets JSON with the
same counts and a `confirm` token; posting that token back completes the
import and redirects to `/?msg=import-ok` as before. Anything that scripted the
old one-step upload needs the second post added.

Vault format is unchanged. No migration.
