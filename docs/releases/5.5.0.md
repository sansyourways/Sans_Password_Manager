# Sans Password Manager 5.5.0

The browser-extension and platform backlog, plus a contact-email cleanup. No
format change: 5.5.0 reads and writes exactly the vaults 5.4.0 does.

## What's new

### Browser-extension password capture (roadmap 39)

The extension autofilled but could never save. Now, when you submit a login
form, it offers **"Save to SPM?"**; on your click it creates a new password —
or updates the one already scoped to that site and username — through a new
`bridge-save` path.

This is the extension's **first write path**, and it is deliberately narrow:

- only from an **unlocked session** (the native host enforces it),
- only for the page's **exact host**, read from the browser's own view of the
  frame — never a hostname the page supplies,
- only on an **explicit click**,
- the new password travels on **stdin, never the argument vector**, so it never
  appears in a process listing, and only `{ok}` is ever returned.

Every save goes through the same row format and history the CLI's own writes use.

### Browser-extension password generator (roadmap 40)

A strong password generated **on the device** with `crypto.getRandomValues`
(rejection-sampled to avoid bias, one of each character class guaranteed,
visually ambiguous characters left out). On a new-password field the picker
offers **"Generate strong password"** and fills the password and confirm boxes;
the popup has a **Generate password** button that generates one and copies it. No
vault and no unlock — generation needs neither.

### Native desktop launcher (roadmap 41)

`spm desktop` is a one-command way to open SPM: it starts the local Dashboard on
loopback, waits for it, and opens it in your browser — an **app window** on a
Chromium-family browser, otherwise your default browser — and stays attached so
Ctrl-C stops it. Each release also carries desktop-integration launchers (a Linux
`.desktop`, a macOS `.command`, a Windows `.cmd`) that all just run `spm desktop`.

There is no bundled browser engine: the window is your own browser, keeping SPM
the small bash-and-Python program it is.

### Windows / WSL first-class support (roadmap 42)

SPM now runs first-class on Windows through **Git-Bash** or **WSL**:

- `install.sh` detects Git-Bash/MSYS/Cygwin and installs to a per-user prefix
  (`~/.local/bin`) that is already on `PATH`; under WSL it installs like any
  other Linux userland.
- `spm.cmd` and `spm.ps1` shims (in `packaging/windows/`) run SPM under Bash or
  WSL, so `spm ...` works from a PowerShell or cmd prompt.
- `spm desktop` opens the Dashboard in your Windows browser — from WSL over
  WSL2's localhost forwarding, using `wslview` or `cmd.exe`.
- The documentation gains a "Windows and WSL" section, and the release keeps its
  Scoop manifest.

## Compatibility

- **No format change.** 5.5.0 stays on vault format 6. The new write path,
  launcher and Windows shims do not change how a vault is stored or read.
- **The extension's write path is opt-in and gated.** It writes only from an
  unlocked session, for the page's exact host, on an explicit click; the
  credential reaches only the localhost native host.

## Testing

The core suite gained a `bridge_save` test (creates a bound password, updates a
matching one, refuses a blank host or password, secret-free). The native-host
regression asserts `save` writes only from an open session and is refused when
locked, and returns no secret. The shell suite runs `bridge-save` through the
CLI and checks the desktop launcher. The packaging block checks the desktop
launchers and the Windows shim, and asserts every published contact is
`sans@silentprotocol.top`. The extension's shared `spmGeneratePassword` is
covered for length and character classes.

## Upgrading

Nothing to do. Reinstall or redeploy the Dashboard. Your vault is untouched. The
extension's save prompt and generator, and the desktop launcher, are all opt-in.
