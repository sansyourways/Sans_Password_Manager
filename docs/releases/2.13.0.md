## Highlights

**Change the master password from the SPM Dashboard.** A new **Settings** group
in the sidebar, with a gear-marked **Master Password** page at `/settings`. It
asks for the current password, the new one and a confirmation, then re-encrypts
the vault in place — the same operation `spm change-master` performs, now
reachable without dropping to a terminal.

The ordering is the load-bearing part. The CLI writes the recovery file
*before* it touches the vault, so a vault whose recovery metadata is missing or
corrupt fails while the old ciphertext is still the live one. The dashboard
keeps that order exactly: a vault re-encrypted under a new password while its
`.recovery` file still names the old one is the single state `spm forgot`
cannot recover from, and that file plus its private key is the last way in. A
vault carrying no usable `META_RECOVERY_PUBKEY` is refused outright and left
byte-identical.

Changing the password signs out every other browser session immediately. Each
one holds a password in memory that no longer opens anything, and waiting for
their next poll to notice would leave them showing a vault they can no longer
read. The session that made the change is re-keyed in place and continues
without a re-login. The previous vault is kept as `.bak` and as a history
snapshot, both still under the old password.

## Changed

**Biometric Unlock moved from Tools into the new Settings group.** Its URL
(`/unlock/settings`) is unchanged, so existing links and bookmarks still work.
It sits beside the master password because both answer the same question — how
this vault gets opened — and having one of them under Tools made the gear a
half-answer.

A new master password must be at least **12 characters**. The CLI has never
enforced a floor, which is a gap rather than a decision worth copying: this is
the one password protecting every other one, and nothing rate-limits an
attacker who already holds the vault file. `spm change-master` is deliberately
left alone in this release rather than changed underneath existing scripted
use, so the two surfaces differ on this point until that is addressed directly.

## Upgrading

Nothing to do. No vault format change, no migration, and the CLI path is
untouched. The page is only reachable from an authenticated session and is
covered by the same CSRF and same-origin checks as every other write.

## Verification

`bash -n`, the generated dashboard server under `ast.parse`, and the full
regression suite pass. The flow is driven end to end against the live server:
each of the five refusals — wrong current password, mismatched confirmation,
too short, unchanged, and an unusable recovery key — asserts the vault is
byte-identical afterwards; the recovery file is decrypted with the test private
key and asserted to hold the *new* password; the old password is asserted to no
longer open the vault; the `.bak` is asserted to still open with it; and a
second session is asserted to be signed out while the acting one survives. A
mutation that wrote the old password to the recovery file was applied and
confirmed to fail the suite for the right reason.
