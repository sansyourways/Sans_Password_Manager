Codebase review

What works—and what strains

The project already demonstrates strong security judgment. The biggest risk is architectural concentration: too many responsibilities inside one very large application script.

● Strong
Explicit threat modelClearly communicates what the system does and does not defend against.
Atomic vault writesTemporary staging, restrictive permissions and safer replacement semantics reduce corruption risk.
Careful temp-file handlingShows real awareness of local attack surfaces.
Conservative browser bridgeHost-aware retrieval is better than unrestricted vault enumeration.
● Mature
Excellent diagnosticsDoctor-style checks turn operational safety into a first-class feature.
Feature completenessTOTP, attachments, history, recovery, sync, browser support and web mode are substantial.
Good documentationSecurity tradeoffs and operational behavior are documented unusually well.
Local-first philosophyUsers retain ownership of vaults, backups and recovery material.
● Architecture debt
Monolithic primary scriptAddressed: vault cryptography now lives in one reviewable core, and the shipped script is generated from source files rather than written as one.
Bash complexity ceilingHTTP, concurrency, parsing and evolving crypto policies are costly to assure in shell.
Implicit crypto policyAddressed: the vault records its format version and derivation is pinned, so a local gpg.conf can no longer change a security parameter underneath the application.
● Operational risk
Recovery designRecovery should ideally wrap a vault key, not recreate access by protecting the master password itself.
Dependency installationAutomatic package installation broadens privilege and maintenance scope.
Testing frontierNext step is fault injection, fuzzing, concurrency stress and kill-during-write testing.

Keep the trusted computing base tiny

Crypto, key handling and vault mutation should live in the smallest possible component. Every UI and integration talks to it through a narrow contract.

Version every security decision

Vault format, KDF parameters, cipher choices, migration rules and recovery metadata should all be explicit and migratable.

Feature strategy

Build the foundation before the fireworks

A staged roadmap that prioritizes security architecture first, then user capability, then ecosystem expansion.

Phase 1 — Foundation

Make the core auditable

Vault-key architectureShipped
Random vault key, separately wrapped by master password and recovery.
Versioned vault format + explicit KDF policyShipped
Format version recorded in the vault; derivation pinned rather than inherited.
Argon2idP0
Not reachable on supported platforms: OpenPGP string-to-key offers no memory-hard function, and Argon2 needs OpenSSL 3.2+ (Debian/Ubuntu ship 3.0; macOS ships LibreSSL). The data-layer replacement brings scrypt; Argon2id follows a platform floor that can test it.
Modular coreShipped
One trusted core; CLI, Dashboard and browser bridge are clients of it.
doctor --jsonP1
Machine-readable diagnostics.
